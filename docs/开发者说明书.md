## 0. 项目定位与免责声明

**它是什么**：一个第三方桌面客户端，直接对接飞牛 NAS 自带「飞牛音乐」的 Web 接口，让你在电脑上听 NAS 里的歌，不用开浏览器。

**它不是什么**：不是飞牛官方产品，不代表飞牛；不破解付费内容；不绕过账号体系——登录仍然走飞牛自己的 OAuth 页面，权限仍然是账号本身的权限。

**风险提示**

- 接口是逆向官方 Web 前端得到的，**官方改版就可能失效**，本项目不承诺长期兼容。
- 签名用的 `secret` / `apiKey` 是官方前端 bundle 里的客户端常量，不是服务端密钥；公开源码时请保留出处说明，若权利人提出异议应移除。
- 请只用于访问**你自己拥有或获授权**的 NAS；不要做批量扫描、爬取、商业分发。
- 代码按「现状」提供，不提供任何担保。

## 1. 三分钟跑起来

### 1.1 环境

| 依赖 | 版本 | 说明 |
|---|---|---|
| Node.js | ≥ 18（推荐 20/22/24） | 本地服务用到全局 `fetch`、`Readable.fromWeb` |
| Electron | 33.x | 仅桌面壳需要；纯 Web 调试可不装 |
| 操作系统 | Windows / macOS / Linux | 开发期在 Linux（无桌面）用 xvfb 跑 |
| 网络 | 能访问 NAS 的 5000 端口 | fnOS 默认 HTTP 5000 / HTTPS 5001 |

### 1.2 从源码运行

```bash
git clone <repo> && cd fnmusic-player
npm i -D electron            # 国内可加 ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/

npx electron .               # 桌面版
# 或者只跑本地 Web 版，浏览器打开 http://127.0.0.1:7311
npm start
```

首次启动没有配置，会弹出「连接飞牛 NAS」：

1. 填地址，例如 `http://192.168.1.10:5000`（只填 IP 也可以，HTTP 会自动补 5000）
2. 点「连接并登录」→ 弹出飞牛登录页
3. 登录（若账号开了两步验证，需要输入 OTP）
4. 成功后自动关闭登录窗、刷新主界面

> 调试时也可以手动粘贴 `music-token`，见 1.3。

### 1.3 手动 token（调试/浏览器模式）

`music-token` 存在 NAS 的 SQLite 里（`trim.music/db/music.db` 的 `user_token` 表），有 SSH 权限时可以自己取一条有效的：

```bash
sudo sqlite3 /usr/local/apps/@appdata/trim.music/db/music.db \
  "select token from user_token order by expired_at desc limit 1;"
```

把它粘进登录弹窗的「手动 token」即可。**这是调试手段，不要写进代码或提交到仓库。**

### 1.4 打包

```bash
# 免安装 zip（Windows）
# 下载 electron-v33.x-win32-x64.zip，解压后把本仓库放进 resources/app，exe 改名 FnMusic.exe

# NSIS 安装包（Linux 交叉编译，不需要 wine）
sudo apt install nsis
cd build && makensis installer.nsi
```

## 2. 架构总览

### 2.1 总体结构

```
┌─────────────────────────────────────────────────────────────┐
│ Electron 主进程 (electron/main.mjs)                          │
│  · 创建窗口，加载 http://127.0.0.1:<随机端口>                 │
│  · 启动本地 HTTP 服务 (server/index.mjs)                     │
│  · 拦截 OAuth 登录窗的 redirect，抢 code                      │
└───────────────┬─────────────────────────────────────────────┘
                │ 加载
┌───────────────▼─────────────────────────────────────────────┐
│ 渲染进程（app/，纯原生 ESM，无构建）                          │
│  index.html + css/style.css                                  │
│  js/api.js     统一请求封装 / 401 → AuthError                 │
│  js/player.js  队列、随机、循环、MediaSession、<audio>        │
│  js/views.js   各页面 HTML 生成（模板字符串）                 │
│  js/app.js     路由、事件绑定、歌词、收藏、登录弹窗            │
└───────────────┬─────────────────────────────────────────────┘
                │ fetch /api/*、/media/*
┌───────────────▼─────────────────────────────────────────────┐
│ 本地 Node 服务 (server/)                                     │
│  index.mjs  静态资源 + 登录接口 + 上游代理 + 音频/封面透传     │
│  nas.mjs    authx 签名、URL 规范化、NAS API 调用              │
│  config.mjs ~/.fnmusic-player/config.json 读写（0600）        │
└───────────────┬─────────────────────────────────────────────┘
                │ HTTP + authx + Cookie: music-token
┌───────────────▼─────────────────────────────────────────────┐
│ 飞牛 NAS：nginx → unix:/var/run/trim_music.socket            │
│ API base: /music/api/v1                                      │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 一次点击到出声

```
点击歌曲行
  → app.js 绑定的事件 → player.playTrack(track, queue)
  → <audio src="/media/stream?guid=...">
  → 本地服务 handleStream()
  → 带 authx + Cookie 请求 NAS /track/stream?guid=...
  → 透传 Range / 206 / Content-Range 回浏览器
  → 音频开始播放
```

歌词、收藏、封面同理，全部经本地服务转发，渲染进程永远不直接访问 NAS。

### 2.3 为什么必须有本地服务

浏览器里直接请求 NAS 会撞三堵墙：

1. **CORS**：NAS 不返回 `Access-Control-Allow-Origin`，跨源读不到响应。
2. **Cookie**：`music-token` 是 NAS 域的 Cookie，`127.0.0.1` 页面带不上。
3. **签名**：每个请求都要 `authx`，且 secret 不能放在公开的前端代码里（虽然本项目最终仍在本地持有）。

本地服务同时解决三者：它是同源（`127.0.0.1`）的，能安全持有 token、能算签名、能加 Cookie，还能把 Range 原样透传。附带好处：token 不出本机、渲染进程拿不到 token。

### 3.3 `server/` 本地服务

#### `server/index.mjs`（272 行）

HTTP 服务入口，零依赖（只用 node 内置模块）。

**路由表**

| 路径 | 方法 | 作用 |
|---|---|---|
| `/api/state` | GET | 当前登录态、host、音量、上次页面 |
| `/api/host` | POST | 校验并保存 NAS 地址；调 `/sys/config` 验证连通性、取 clientId |
| `/api/auth/url` | GET | 生成 OAuth 登录 URL（`/signin?client_id&redirect_uri&app_name`） |
| `/api/auth/callback` | POST/GET | 用 `code` 换 `userToken`（`/user/auth-login`） |
| `/api/auth/manual` | POST | 手动 token 登录（`/user/me` 验证） |
| `/api/logout` | POST | 调上游 `/user/logout` 并清本地 token |
| `/api/prefs` | POST | 保存音量 / lastView / host |
| `/api/v1/*` | 任意 | 透传到 NAS 同名接口，自动加 `authx`、Cookie |
| `/media/stream` | GET/HEAD | 音频流，透传 Range / 206 |
| `/media/cover` | GET | 封面，浏览器缓存 1 天 |
| `/health` | GET | 健康检查（返回 apiKey 前 4 位，仅用于确认版本） |
| 其它 | GET | 静态文件（`app/`），路径穿越防护 |

**实现要点**

- `requireAuth()`：无 token 抛 401。
- `handleProxy()`：`/api/v1/xxx` → `/music/api/v1/xxx`；上游 `code=99999` 视为登录失效，清 token 并返回 401。
- `handleStream()`：只转发必要头（`content-type/length/range/etag/last-modified`），用 `Readable.fromWeb().pipe(res)` 流式回传，不落盘、不整段读内存。
- `handleCover()`：同样带签名和 Cookie，命中后 `Cache-Control: public, max-age=86400`。
- `serveStatic()`：`path.normalize` 后校验必须以 `APP_DIR` 开头，防 `../`。
- 错误统一 `{code, msg, data}`，前端只认 `code === 0`。

#### `server/nas.mjs`（89 行）

与 NAS 打交道的底层。

| 导出 | 说明 |
|---|---|
| `SECRET` / `API_KEY` | 官方前端里的签名常量（见第 5 章） |
| `md5(s)` | 十六进制 MD5 |
| `buildAuthx(pathname, {params, bodyBytes})` | 生成 `nonce=...&timestamp=...&sign=...` |
| `normalizeHost(input)` | 补协议、去尾斜杠；HTTP 无端口补 5000，HTTPS 保持 443 |
| `deviceId()` | 32 位 hex，登录设备标识 |
| `apiUrl(host, path, params)` | 拼 `/music/api/v1/...` |
| `nasApi(host, token, path, opts)` | 统一调用：签名、Cookie、JSON、20s 超时、99999 抛错 |

**签名细节（最容易写错的地方）**

```
GET  : 参数按 key 排序 → encodeURIComponent → 空格用 %20 → 拼 k=v&...
       → 整体 decodeURIComponent → md5 → bodyhash
POST : md5(原始 JSON 字符串) → bodyhash
sign = md5(SECRET_path_nonce_timestamp_bodyhash_API_KEY)
```

注意 `pathname` 必须带 `/music` 前缀（如 `/music/api/v1/track/list`），否则签名对不上。

#### `server/config.mjs`（59 行）

本地配置存储，路径 `~/.fnmusic-player/config.json`（可用 `FNMP_HOME` 覆盖，测试时很有用）。

```json
{
  "host": "",
  "token": "",
  "user": null,
  "deviceId": "32位hex",
  "volume": 0.85,
  "lastView": "#/tracks",
  "clientId": "从 NAS 动态获取",
  "serverName": ""
}
```

- `load()` 带内存缓存；文件不存在/损坏就用默认值。
- `save(patch)` 原子写（tmp + rename），目录 0700、文件 0600。
- `publicState()` 只暴露 host/loggedIn/user/volume/lastView，**绝不把 token 返回给前端**。
- `clearAuth()` 清 token 和 user。

### 3.4 `electron/` 桌面壳

#### `electron/main.mjs`（238 行）

| 函数 | 说明 |
|---|---|
| `finishLogin(code)` | POST 本地 `/api/auth/callback`；成功后关登录窗、刷新主窗 |
| `isOAuthResult(url)` | 判断是否 `/music/oauth/result`（兼容 `/oauth/result`） |
| `openLoginWindow(url)` | 540×760 登录窗，`persist:fnmusic-login` 分区保留 NAS 登录态 |
| `createWindow()` | 1320×840 主窗，最小 980×620；拦截 `window.open` |
| 调试钩子 | `FNMP_SHOT` / `FNMP_DUMP` / `FNMP_EVAL`，见第 7 章 |

**OAuth 拦截的关键**：在 `will-redirect` / `will-navigate` 里先 `event.preventDefault()`，再取 URL 上的 `code`。不拦截的话，登录窗会继续加载音乐 SPA，SPA 会先用掉这个**一次性 code**，我们再换 token 就必然失败。`did-navigate` 只作为兜底（无法阻止导航）。

**其它**：`app.setName('飞牛音乐')`；macOS 关窗不退出；退出前 `server.close()`；F12 / Ctrl+Shift+I 开 DevTools。

## 4. 开发过程复盘

### 4.1 时间线

| 阶段 | 做了什么 | 产出 |
|---|---|---|
| 1. 摸底 | 看端口、nginx 反代、应用目录 | 确认 `/music` → `trim_music.socket`，应用在 `@appcenter/trim.music` |
| 2. 找接口 | 读前端 bundle，提取路由表 | 拿到 `album/track/artist/lyric/...` 全部端点 |
| 3. 破签名 | 定位 `uk()` 函数，还原 MD5 拼串 | `buildAuthx()` 可用 |
| 4. 拿 token | OAuth 调试受 2FA 阻塞 → 直接读 SQLite `user_token` | 打通所有 GET 接口 |
| 5. 实测 | 写 `api_probe.py` 逐个接口试参数 | 修正 `q` / `guid` / `size` 等关键参数 |
| 6. 服务端 | `nas.mjs` + `index.mjs`，代理、流、登录 | `/health`、`/api/v1/*`、`/media/stream` 可用 |
| 7. 前端 | 原生 ESM 写路由、视图、播放器 | 11 个路由跑通 |
| 8. 桌面壳 | Electron + OAuth 拦截窗 | 登录闭环 |
| 9. 验证 | xvfb + `executeJavaScript` 做 DOM 断言 | 播放、歌词、收藏、分页全绿 |
| 10. 打包 | zip → NSIS 安装包 | 两个 Windows 产物 |

### 4.2 五个关键突破

1. **签名算法**：不是简单 `md5(query)`，而是「排序 → 编码 → 拼串 → **解码** → md5」。少一步 `decodeURIComponent` 就永远 401。
2. **token 来源**：与其硬啃 OAuth，不如先读数据库拿一条现成 token 把接口跑通；OAuth 留到最后做。这个顺序省了大量时间。
3. **本地代理**：一次性解决 CORS、Cookie、签名、Range 四个问题，还顺带把 token 藏在主进程侧。
4. **抢 code**：OAuth code 是一次性的，必须在 SPA 加载前 `preventDefault()`，否则必失败。
5. **交叉打包**：Linux 上不装 wine，用 `makensis` 编安装包、用纯 JS 的 `resedit` 改 PE 资源。

### 4.3 踩坑清单（省得再踩）

| 坑 | 结论 |
|---|---|
| 分页传 `pageSize` / `limit` / `offset` | 全部无效，正确参数是 `size`，默认 50 |
| `/album/detail` 传 `albumGUID` | 报 100002，正确是 `guid` |
| `/search/track` 传 `keyword` | 报 100002，正确是 `q` |
| `/track/stream` 传 `trackGUID` | 返回 200 但内容是 JSON 错误，正确是 `guid` |
| `/track/lyrics` | 落到 SPA HTML，正确是 `/lyric/list?trackGUID=` |
| 专辑排序 `title,asc` | 被静默回退到默认排序，正确字段是 `name` / `releaseYear` |
| 歌曲排序 `updatedAt,desc` | 同上，可用字段：`createdAt` / `title` / `trackNumber` |
| 登录窗 `window.open` 返回 `null` | 主进程 `setWindowOpenHandler` 返回 `deny` 时必然为 null，不能据此判断失败 |
| OAuth code 换 token 失败 | 多半是 SPA 抢先消费了 code，必须 preventDefault |
| 无头 Electron 报 GPU 错 | 用 `xvfb-run`，错误可忽略；截图/DOM 正常 |
| ZIP 内中文文件名 | Info-ZIP 会写成 `#U98de#U...`，Windows 解压乱码 → exe 名用 ASCII |
| `makensis` 输出中文名/反斜杠 | Linux 下不认，`OutFile` 用正斜杠 + ASCII，编完再改名 |
| CSP 下内联 `onerror` 失效 | 改成全局捕获 `document.addEventListener('error', …, true)` |

## 5. 接口逆向笔记

> 完整端点表见 `docs/API.md`。这里只讲原理和最容易出错的点。

### 5.1 定位

- 入口：`http://<nas>:5000/music/`（80 端口会 302 到 5000）
- 反代：`/usr/trim/nginx/conf/conf.d/` 里 `/music` → `unix:/var/run/trim_music.socket`
- 应用：`/usr/local/apps/@appcenter/trim.music/`（Go 二进制 + `static/assets/*.js`）
- 数据库：`/usr/local/apps/@appdata/trim.music/db/music.db`

### 5.2 签名 `authx`

```
nonce     6 位随机数字
timestamp 毫秒
bodyhash  GET  : md5( decodeURIComponent( 排序后的 "k=v&..." ) )
          POST : md5( raw JSON body )
sign      md5( SECRET + "_" + pathname + "_" + nonce + "_" + timestamp + "_" + bodyhash + "_" + API_KEY )
authx     nonce=...&timestamp=...&sign=...
```

`pathname` 必须包含 `/music` 前缀（`/music/api/v1/track/list`）。

### 5.3 OAuth 登录

```
GET  /music/api/v1/sys/config          → nasOAuth.clientId
打开 /signin?client_id=<id>&redirect_uri=<urlencode(http://<nas>:5000/music/oauth/result)>&app_name=飞牛音乐
用户登录（可能触发 OTP）
跳回 /music/oauth/result?code=xxxxx
POST /music/api/v1/user/auth-login     { code, deviceId }
     → data.userToken（即 music-token）、data.user
```

- `code` **一次性**，必须抢在音乐 SPA 之前拿走。
- 自己搭的客户端不要复用官方 clientId 做违规用途；每台 NAS 的 clientId 从 `sys/config` 动态取。
- `password-login` 只适用于音乐应用内自建用户；NAS 同步用户会返回 `120001`。

### 5.4 常用端点

| 功能 | 端点 | 关键参数 |
|---|---|---|
| 歌曲列表 | `GET /track/list` | `page`、`size`、`sort` |
| 专辑列表/详情 | `GET /album/list`、`/album/detail` | `page`/`size`；详情用 `guid` |
| 专辑曲目 | `GET /track/album-detail/list` | `albumGUID` |
| 歌手 | `GET /artist/list`、`/artist/detail` | `guid` |
| 歌单 | `GET /playlist/list`、`/playlist/detail` | `guid` |
| 收藏 | `GET /favorite-track/list`；`POST /favorite-track/create|delete` | `{trackGUID}` |
| 文件夹 | `GET /folder-view/list` | `parentPath`（必须是真实共享库路径，`/` 会 100005） |
| 搜索 | `GET /search/track|album|artist` | `q` |
| 音频 | `GET /track/stream` | `guid`（支持 Range） |
| 封面 | `GET /static/cover` | `coverId` |
| 歌词 | `GET /lyric/list` | `trackGUID` |
| 转码 | `POST /track/transcode` | `{guid, output:{...}, start}` |

### 5.5 分页、排序、错误码

- 分页：`page` 从 1 开始，`size` 默认 50；返回 `{list, total, sort}`。
- 排序白名单（前端校验）：`albumCount`、`artistName`、`createdAt`、`name`、`newTrackAddedAt`、`releaseYear`、`title`、`trackCount`、`trackNumber`。
- 传了白名单外的字段不会报错，而是**静默回退默认排序**——调排序没生效先怀疑字段名。
- 常见错误码见附录 A。

## 6. 关键实现细节

### 6.1 代理层为什么这么写

`handleProxy` 不做任何业务判断，只做四件事：拼路径、签名、带 Cookie、透传响应。这样上游新增接口时，前端改个路径就能用，服务端不用动。

副作用：`/api/v1/*` 等于把整个音乐 API 暴露给了渲染进程。因为渲染进程加载的是本地可信代码、且窗口禁用了 `nodeIntegration`，这个暴露面是可接受的；但如果将来要嵌第三方页面，必须加能力白名单。

### 6.2 Range 透传

音频拖动进度依赖 `Range`：

- 请求带 `Range: bytes=...` 时原样转发；
- 响应保留 `206`、`Content-Range`、`Content-Length`、`ETag`、`Last-Modified`；
- 用流式 pipe，避免整首歌进内存。

缺 `Accept-Ranges` 或把 206 改成 200，都会导致进度条不能拖或重复下载。

### 6.3 登录窗与 code 拦截

```
渲染进程 window.open(authUrl)
  → 主进程 setWindowOpenHandler 拦截（deny）
  → openLoginWindow(authUrl)
  → 用户登录
  → will-redirect / will-navigate 命中 /music/oauth/result
  → preventDefault() + 取 code
  → POST 本地 /api/auth/callback
  → 服务端换 token、写配置
  → 主窗 location.reload()
```

渲染进程这边因为 `window.open` 返回 `null`，不能靠 `w.closed` 判断，只能轮询 `/api/state`。

### 6.4 播放器状态

- 单一 `<audio>` 元素，事件驱动 UI；
- `timeupdate` 更新进度与歌词高亮（按时间二分/线性找当前行）；
- `ended` → `next(true)`，受 `repeat` 影响；
- MediaSession 的 `metadata` 用封面代理 URL，系统媒体面板能显示封面；
- 音量持久化走 `savePrefs`，下次启动恢复。

### 6.5 歌词

`/lyric/list` 返回 `data.list[].content`，可能是多段 LRC。解析：

```
[mm:ss.xx]文本  → { time: 秒, text }
```

支持一行多时间标签；无时间标签的行忽略。点击歌词行 `seek` 到对应秒数。

### 6.6 安全策略

| 项 | 做法 |
|---|---|
| 监听地址 | 只绑 `127.0.0.1`，不对外 |
| token | 只在主进程/服务端；`publicState()` 不返回 |
| 文件权限 | 配置目录 0700、文件 0600 |
| XSS | 所有插值 `escapeHtml`；CSP 禁外链脚本 |
| 路径穿越 | 静态服务校验 `file.startsWith(APP_DIR)` |
| 上游错误 | 统一包装，不把内部堆栈返回前端 |
| 遥测 | 无，任何第三方请求都没有 |

## 8. 打包与发布

### 8.1 免安装 zip

1. 下载 `electron-v33.x-win32-x64.zip` 并解压；
2. 在 `resources/app/` 放：`app/ server/ electron/ build/ docs/ package.json`；
3. `electron.exe` 改名 `FnMusic.exe`（**必须 ASCII**，原因见 8.4）；

### 8.2 NSIS 安装包（Linux 交叉编译）

```bash
sudo apt install nsis
cd build && makensis installer.nsi
# 输出 ../dist/fnmusic-setup-0.1.0.exe（约 80 MB，LZMA solid）
```

脚本要点：

- `Unicode true` + `MUI2`，简体中文界面；
- `RequestExecutionLevel user` → 装到 `%LOCALAPPDATA%\Programs\FnMusic`，不需要管理员；
- `File /r "../dist/fnmusic-win32-x64/*.*"` 打入整个应用目录；
- 写 `HKCU\...\Uninstall\FnMusic`，支持「设置 → 应用」卸载；

### 8.3 图标与版本信息

```bash
node scripts/patch-exe.mjs <原始exe> build/icon.ico <输出exe>
```

`resedit` 直接改 PE 的 `RT_ICON` / `RT_VERSION`，不需要 wine。脚本会替换图标组并写入 `ProductName/FileVersion` 等字段。**改完务必用 `file` 确认仍是 `PE32+ executable`**。

### 8.4 文件名编码坑（重要）

Info-ZIP 在 Linux 上压缩非 ASCII 文件名时会写成 `#U98de#U725b...`，Windows 资源管理器解压后就是乱码文件名。规避：

- 压缩包内所有文件名用 ASCII（`FnMusic.exe`、`README.txt`）；
- 中文只放在**文件内容**和**快捷方式显示名**里；
- 压缩包本身的下载名可以用中文（HTTP 头是 UTF-8）。

同理，`makensis` 在 Linux 下 `OutFile` 不要用中文和反斜杠：先用 `../dist/fnmusic-setup-0.1.0.exe` 编，再重命名。

## 10. 如何继续开发

### 10.1 加一个新页面

1. `app/js/views.js` 写 `renderXxx()`，设置 `ctx.route/ctx.tracks/ctx.more`，返回 HTML；
2. `app/js/app.js` 的 `route()` 加 `case 'xxx'`，设置标题并 `await views.renderXxx()`；
3. `app/index.html` 侧栏加 `<a data-nav="xxx" href="#/xxx">`；
4. 需要新样式就加在 `style.css` 对应分区。

### 10.2 加一个新接口

1. 确认端点和参数（用 `docs/API.md` 的方法实测）；
2. 前端直接 `api('/new/path', {params})`，服务端 `/api/v1/*` 会自动代理，**通常不用改服务端**；
3. 只有需要特殊处理（二进制、非 JSON、额外头）才在 `server/index.mjs` 加独立路由。

### 10.3 加播放器能力

- 队列操作改 `player.js`，通过 `emit('track'|'state')` 通知 UI；
- UI 更新在 `app.js` 的 `renderNowPlaying/updateProgress/renderQueue`；
- 需要系统集成（媒体键、任务栏）优先用 MediaSession 和 Electron 主进程 API。

### 10.4 改签名/兼容新版

如果飞牛升级后 401：

1. 打开新版 `/music/` 的 `static/assets/*.js`，搜 `authx` 或 `nonce=`;
2. 找生成 `sign` 的函数，确认拼串顺序、是否新增字段；
3. 同步改 `server/nas.mjs` 的 `buildAuthx()`；
4. 用 `/sys/config` 做最小验证（不需要登录）。

## 附录 A：错误码

| code | 含义 | 处理 |
|---|---|---|
| `0` | 成功 | — |
| `99999` | INVALID TOKEN / 未授权 | 清 token，重新登录 |
| `120001` | 未授权（OAuth 用户走密码登录时常见） | 改用 OAuth |
| `100001` | unknown error（如 code 无效/过期） | 重新走登录 |
| `100002` | invalid arguments（参数名/类型错） | 对照文档检查参数 |
| `100005` | resource not found（路径/guid 不存在） | 检查 `parentPath`、`guid` |
| HTTP 401 | 本地服务判定未登录 | 前端弹登录框 |
| HTTP 502 | 上游不可达/返回异常 | 检查 NAS 地址、网络、服务状态 |

## 附录 B：FAQ

**Q：为什么不用浏览器直接连 NAS？**
A：CORS、Cookie 域、请求签名三座山，必须有本地代理。见 2.3。

**Q：为什么 token 要存在本地文件？**
A：Electron 没有系统钥匙串的统一实现；文件 0600 是当前最简单可靠的方案。后续可接 `safeStorage`。

**Q：登录一直失败？**
A：先确认账号是否开了 OTP；再确认 NAS 地址端口（HTTP 5000 / HTTPS 5001）；最后看主进程日志 `[oauth] callback ...`。

**Q：播放没声音/不能拖进度？**
A：看 `/media/stream` 是否返回 206 和 `Content-Range`；确认上游音频格式浏览器支持（mp3/flac/aac 都行，APE 不行）。

**Q：官方升级后全挂了？**
A：按 10.4 重新对签名；接口字段变化就看新版前端 bundle 的路由表。

**Q：能上架应用商店吗？**
A：不能。这是非官方逆向客户端，且使用了官方客户端常量；只适合自用/开源学习。
